### 🚀 Wayground Pro Automator v4.1

Personal API configuration in the desktop UI, GPT-6 request compatibility, automatic answer-explanation navigation, a standalone HTTPS fix, and experimental Linux/macOS source support.

#### Changes

- **Experimental Linux/macOS support**: Added installed Edge/Chrome/Chromium discovery, XDG and macOS application-data locations, platform-native Playwright caches, and `.env` lookup beside macOS app bundles. Browser retries terminate only the process launched by the program. Linux/macOS shortcuts work while the app is focused; without a tray, hiding minimizes the panel to keep restoration accessible. Wayland dragging uses the system-move API. A shared native build script prepares Windows executables, Linux executables and macOS `.app` bundles; `--dry-run` prints the command without building. A manual GitHub Actions workflow checks all three platforms without producing binaries. See [platform support](../platform-support.md) for requirements and limitations.
- **Personal API settings**: Added API base URL, API key and model fields under **Settings → AI engine → Personal API**, with a startup shortcut. Keys are masked by default, can be revealed, and are redacted from logs, including failed checks and replaced keys. Settings are validated before use and applied only after a successful test. During a run, a checked engine is queued for the next AI request. UI-entered credentials remain in memory until the app closes; `.env` remains available for configuration across restarts.
- **GPT-6-compatible requests**: Uses `max_completion_tokens` with room for reasoning and omits custom temperature. For other API models or aliases, explicit parameter-rejection errors trigger bounded compatibility retries. Successful capabilities are cached for the API URL and model, then shared by the connection check, multiple-choice solver and fill-in-the-blank solver.
- **Meaningful availability checks**: Replaced the direct API `ping` with a test question requiring the correct JSON answer. Empty, malformed, wrong and truncated replies are rejected. Failed custom API checks retain the previous engine configuration.
- **Answer-explanation panels**: Detects Wayground's `answer-explanation-container` and uses its own **Next question** control, including clickable `div` elements and English, Russian and Ukrainian labels. Handles delayed panels, waits for closure before reading a question, and preserves pause, Stop and session guards. An explanation without a ready control blocks underlying question and navigation actions.
- **Standalone HTTPS initialization**: Includes the SSL runtime's required PEM resource in Windows builds, fixing `[Errno 2] No such file or directory` before API requests. Added API-client construction to the executable smoke check to catch missing SSL resources.

#### Validation and build status

- On Windows, the source passed 342 automated tests, 15 local headless-browser checks and 45 desktop smoke checks, including TLS-client initialization. These checks do not verify live provider credentials or account access.
- Linux/macOS path, browser, launcher and build-command branches have regression coverage on Windows. Native Linux/macOS verification remains pending; the manual CI workflow has been prepared but has not been run.
- Application version: `4.1`. Windows file version: `4.1.0.0`.
- No v4.1 binaries have been built. The Windows output remains `dist/4.1/WaygroundAutomator.exe`; Linux and macOS build preparation is documented in the platform guide. Signing/notarization and native Linux/macOS release validation remain pending.
